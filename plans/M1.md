# M1: Tracing core, store and CLI

GOAL: An offline, tested core: instrument a pipeline's steps with OpenTelemetry, store spans in
SQLite with redaction, classify and cluster failures, and inspect them from a CLI. See
plans/ROADMAP.md.

SCOPE: `src/failure_forensics/` (keep the package name), `examples/`, `tests/`, `pyproject.toml`/
`uv.lock`, `README.md`, `DECISIONS.md`, `CHANGELOG.md`.

DO NOT TOUCH: `plans/`, `AGENTS.md`, `CLAUDE.md`, `.github/` (unless a new test needs nothing extra
— then leave it), other repos. Never read `.env`. No network, no LLM calls.

STEPS:
1. **Dependencies**: `opentelemetry-api` and `opentelemetry-sdk` only (no exporters/collector).
   Python ≥ 3.12. Add an `ff` console script (keep the long name as an alias).
2. **Tracing API** (`trace.py`):
   - `with ff.run(name, case_id=None, tags=…) as run:` starts a root span = one pipeline run.
   - `@ff.step("validate")` decorator and `with ff.step("execute", **attrs):` context manager
     create child spans; they record inputs/outputs via `step.record(input=…, output=…)` (values
     serialised to JSON safely, truncated to a configurable size, then redacted), status, exception
     (type, message, short traceback hash), and duration.
   - `ff.mark_failure(kind, detail)` lets the pipeline flag a *semantic* failure (e.g. "blocked",
     "wrong_result") without an exception.
   - Works for sync and async functions; nested steps; thread-safe via OTel context.
3. **Store** (`store.py`): an OTel `SpanExporter` writing to SQLite (WAL mode): tables `runs`,
   `spans` (trace/span/parent ids, name, start/end ns, status, attributes JSON), `failures`.
   Schema version table + simple migrations. Batch processor flush on run end. Path from
   `FF_DB` env or `--db`, default `./.ff/traces.db` (git-ignored).
4. **Redaction** (`redact.py`): applied before storage: emails, phone numbers, IBAN/credit-card
   like numbers (Luhn), bearer tokens / API-key-like strings (`sk-…`, long hex/base64), plus
   caller-supplied regexes and key names (`password`, `token`, `secret`, `authorization`).
   Tests for each, including no false positives on SQL like `SELECT id FROM orders`.
5. **Failure classification** (`classify.py`): for each run, the **first failing step** (earliest
   span end with error or marked failure) is the culprit; kinds: `exception`, `timeout`,
   `refusal`, `blocked`, `wrong_result`, `empty_output`, `marked:<custom>`; pluggable rules (a
   rule gets the run's spans, returns a Failure or None). Error **signature** = step name + kind +
   normalised message (numbers, quoted literals, uuids, hex ids and paths replaced by
   placeholders) → used for clustering.
6. **Clustering** (`cluster.py`): group failures by signature; report count, first/last seen,
   example run ids, and the share of runs. Optional second-level grouping by tag.
7. **CLI** (`cli.py`): `ff runs [--failed] [--since]`, `ff show <run_id>` (indented text waterfall
   with durations and the culprit step highlighted, inputs/outputs truncated), `ff failures`,
   `ff clusters [--top N]`, `ff gc --keep-days N`. Exit 0; 3 on usage/db errors. Output is plain
   text, stable for golden tests; `--json` everywhere.
8. **Example** (`examples/toy_pipeline.py`): a small offline "question → plan → tool → answer"
   pipeline with seeded fault injection producing several distinct, known failure clusters
   (exception in tool, timeout, blocked by a policy step, wrong answer vs a gold value, empty
   output). `examples/run_demo.sh` runs 100 seeded cases into `examples/demo.db` (committed if
   < 1 MB, otherwise regenerated by the script) and prints `ff clusters`.
9. **Tests**: span tree shape (nesting, async, exceptions), store round-trip and migrations,
   redaction (positive + negative cases), classifier (first failing step wins; marked failures;
   timeout), signature normalisation, clustering counts on the seeded demo (exact expected
   clusters), CLI golden outputs, `gc`. Use a temp DB per test.
10. Docs: README (what/why, 30-second quick start with the demo, how to instrument your own
    pipeline in 10 lines, redaction defaults, limits), DECISIONS (OTel + own SQLite exporter instead
    of a collector; first-failing-step rule; signature normalisation), CHANGELOG.

- `examples/run_demo.sh` produces the expected clusters; `ff show` on one failing run shows the
  culprit step.
- NOTES describe the clusters the demo produces.
