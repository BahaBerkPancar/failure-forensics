# M3: UI (Streamlit)

GOAL: A local Streamlit app (`ff ui --db traces.db`) for looking at runs and failures: the screens a
person uses after a bad deploy. Read-only over the SQLite store. Looks deliberate, not like a
default Streamlit demo.

SCOPE: `src/failure_forensics/ui/` (app + pure data functions), `cli.py` (`ff ui`), `pyproject.toml`
(Streamlit as an optional `ui` extra), `tests/`, `docs/` (screenshots), README/DECISIONS/CHANGELOG.

DO NOT TOUCH: other repos, `plans/`, `AGENTS.md`, `CLAUDE.md`. Never read `.env`. No network beyond
localhost; disable Streamlit telemetry (`browser.gatherUsageStats = false` in a bundled
`.streamlit/config.toml` or via flags); bind 127.0.0.1 only.

STEPS:
1. **Data layer** (`ui/data.py`, no Streamlit imports, fully tested): runs table query with filters
   (status, name, tag, time window, culprit step, cluster), run detail (span tree with timings,
   inputs/outputs, error, culprit), clusters with counts per hour/day bucket, and a "nearest
   passing run" finder for the same case_id (or same name + tags) for side-by-side diff.
   Open SQLite read-only (`mode=ro` URI).
2. **Pages**:
   - **Overview**: totals (runs, failure rate, top clusters), a small failures-over-time chart per
     cluster (Streamlit's native charts; one accent colour + neutrals; legible in light/dark).
   - **Runs**: filterable table; selecting a run opens its detail.
   - **Run detail**: waterfall of spans (horizontal bars by start/duration, culprit highlighted),
     step inputs/outputs (truncated, expandable, rendered as text/JSON — never as HTML/Markdown
     from data: use `st.code`/`st.json`/`st.text`, never `unsafe_allow_html`).
   - **Clusters**: table with signature, count, share, first/last seen, example runs; selecting one
     lists its runs.
   - **Diff**: failing run vs nearest passing run of the same case: step by step, showing which
     step's output first differs.
3. **Design**: custom theme in `.streamlit/config.toml` (calm palette, one accent, readable fonts),
   consistent spacing, no emoji labels, clear empty states ("no failures in this window").
4. **Tests**: data functions on the committed demo DBs (toy + t2s) with exact expectations; the
   app imports and builds each page without a browser via `streamlit.testing.v1.AppTest` (no
   network); a grep test that `unsafe_allow_html` is never used; read-only open proven (a write
   attempt fails).
5. **Screenshots**: run `ff ui --db examples/t2s/demo.db` on 127.0.0.1 (a free port, e.g. 8501),
   take screenshots of Overview, Run detail (a failing t2s run) and Diff with headless system Chrome
   (own temp `--user-data-dir`, own process group, killed afterwards) into `docs/`. Look at them
   with Read and iterate on layout until they look right. Stop the server afterwards.
6. Docs: README "UI" section with screenshots; DECISIONS (Streamlit as optional extra; read-only
   store; diff heuristic); CHANGELOG.

DONE WHEN:
- `uv run pytest && uv run ruff check .` pass without the `ui` extra (UI tests skip) and with it.
- Screenshots exist and look right.

ESTIMATE: 90–120 min.

REPORT: end with the report contract (CHANGED / EVIDENCE / ESTIMATE vs ACTUAL / NOTES / VERDICT).
Do not commit, do not push.
