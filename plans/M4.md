# M4: Failure → test case, and showcase

GOAL: Close the loop "trace → cluster → export → gate": turn failing traces into regression test
cases that run in CI, then make the repo understandable in 30 seconds.

SCOPE: `src/failure_forensics/export/`, `cli.py` (`ff export`), `tests/`, `examples/`,
`docs/` (architecture.svg), README/DECISIONS/CHANGELOG.

DO NOT TOUCH: other repos (model-regression-detector is read-only reference), `plans/`,
`AGENTS.md`, `CLAUDE.md`. Never read `.env`. No network, no LLM calls.

STEPS:
1. **mrd export** `ff export --cluster <signature|prefix> [--limit N] --to mrd --out cases.yaml`:
   writes an mrd suite (the format in
   `/Users/MKRAForce/all_my_projects/model-regression-detector` — read its formats.py/README; do
   not import it) with one case per distinct failing input in the cluster: `id` (stable hash of the
   input), `input` (the run's case input), `expected` taken from the nearest passing run of the same
   case if one exists, otherwise left empty with `needs_review: true`, `tags` (cluster signature,
   step, kind, original tags). `--merge existing.yaml` appends without duplicates.
2. **pytest export** `ff export --cluster X --to pytest --out tests/regressions/test_<slug>.py`:
   a generated, readable pytest file that replays each failing input through a user-supplied entry
   point (`--entry module:function`) and asserts it no longer fails the same way (no exception of the
   recorded type at the culprit step; for semantic failures, a user-provided checker or the expected
   value from the passing run). The generated file must be safe: inputs embedded via `repr`/JSON
   literals only — never via string-built code from untrusted text; test that a hostile input
   (quotes, triple quotes, newlines, `__import__('os')`) produces a valid, inert test file
   (compile it and run it against a stub).
3. **Redaction carries over**: exported inputs are the already-redacted stored values; say so; add
   a `--show-redacted` count in the output so a user knows when an exported case may be incomplete.
4. **End-to-end demo** `examples/loop/run_loop.sh`: toy pipeline → clusters → export the top
   cluster to pytest → the generated test fails on the buggy pipeline → a fixed pipeline flag makes
   it pass. Document the output in the README.
5. **Showcase**: README rewrite (one-line pitch; the loop diagram `docs/architecture.svg`, dark-safe,
   no external fonts; quick start; tracing your own pipeline; t2s example with the UI screenshots;
   export; limits: single culprit per run, pattern-based redaction, copy-of-control-flow for t2s,
   bare 32-hex keys), DECISIONS, CHANGELOG (0.1.0 summary).
6. **Tests**: mrd suite output validates against the documented mrd shape (hand-check with a small
   schema in the test, since mrd isn't a dependency); dedupe/merge; needs_review when no passing
   run; pytest export compiles and behaves on the stub; hostile-input inertness; CLI exit codes.

DONE WHEN:
- `uv run pytest && uv run ruff check .` pass offline (with and without extras).
- `examples/loop/run_loop.sh` shows fail → pass.
- README renders sensibly with relative image paths.
